# 语义摄像头 · Windows 11 上手指南

一页说明，普通 Windows 11 用户按顺序做即可。**不需要安装 Python，不需要管理员权限，不需要联网。**

## 1. 解压

把 zip 解压到任意可写目录（例如 `D:\语义摄像头`）。中文路径也可以。
解压后目录里应当有：

```
语义摄像头\语义摄像头.exe      ← 唯一入口，双击它
语义摄像头\_internal\…         ← 运行库，不要单独移动
语义摄像头\使用说明.md         ← 本文件
语义摄像头\THIRD-PARTY-NOTICES.txt
语义摄像头\win11-manifest.json ← 构建清单（版本与文件哈希）
```

## 2. 双击 `语义摄像头.exe`

- 第一次运行会打开**本机**的“接入第一路摄像头”页面（只监听 127.0.0.1，不对局域网开放）。
- 第二次起直接打开工作台；**不会覆盖已有配置**。
- 数据（配置、数据库、证据图片、日志）全部写在：
  `%LOCALAPPDATA%\semantic-camera`
  发行包目录只读也能正常运行；想卸载直接删目录即可，数据留在上面那个位置。

## 3. 填写第一路摄像头

| 字段 | 说明 |
|---|---|
| 相机 ID | 自定义短名，只允许字母、数字、下划线、短横线（如 `front-door`） |
| 来源类型 | RTSP 摄像头 / 本机摄像头 / 本地视频文件 |
| 来源地址 | RTSP 填 `rtsp://用户名:密码@地址:554/...`；本机摄像头填 `0`；本地文件填完整路径 |
| 人物检测模型（ONNX） | 选择**本机已下载**的 `person-detector.onnx` 完整路径 |
| 仅预览、不告警 | **没有模型文件时必须勾选**，否则无法保存 |

关于模型：本发行包**不随包分发**检测权重。请自行取得 NanoDet-Plus 的人员检测 ONNX
（上游 `RangiLyu/nanodet` 发布资产 `nanodet-plus-m_416.onnx`，校验用 SHA-256：
`59d2f166088889c902f523bf08079391993491324f0d84847e3c4016a8f7cc3d`），
放到本机任意目录后在向导里填它的完整路径。没有模型时，请明确选择“仅预览、不告警”，
系统不会假装自己在检测。

## 4. 圈选区域与规则

工作台里用方格点选要重点管理的区域（例如门口、收银台前），再给区域加规则：
类别（person）、是否要求滞留、以及严重度。**只有管理员定义的规则命中才会告警**，
系统不会自行扩大报警范围。

## 5. 看告警与证据

事件列表里每条告警都带时间、相机、区域、规则和一句中文说明；点“最佳帧”可查看
当时画面（JPEG 证据存放在 `%LOCALAPPDATA%\semantic-camera\evidence`）。
标记误报后，同类场景会逐步转入本地模式复用，减少重复理解成本。

## 6. 正常退出

在工作台窗口按 `Ctrl+C`，或直接关闭控制台窗口。退出后进程与端口都会释放，
可以再次双击启动。

## 常见问题

| 现象 | 处理 |
|---|---|
| 双击后提示“端口 8600 已被占用” | 关闭占用该端口的程序，或右键快捷方式在目标后加 `--port 8601` |
| 双击后提示“已有一个实例在运行” | 说明已经启动过了，直接用已打开的工作台页面，不要重复启动（会争用数据库） |
| 提示“录像/片段导出不可用：未找到 ffmpeg” | 预览与管理员规则告警不受影响；需要录像时再单独安装 ffmpeg |
| 提示“检测模型不存在/加载失败” | 向导里填的 ONNX 路径不对或文件损坏；改填正确路径，或改为“仅预览、不告警” |
| 相机一直连不上 | 检查 RTSP 地址、用户名密码与网络；工作台健康区会给出中文原因 |
| Windows 提示“未知发布者/已阻止” | 本发行包**未做代码签名**。请只运行你自己或信任来源提供的包；不要在系统安全设置里关闭防护 |

## 更新发行包（不丢数据）

1. 解压新版本到**另一个目录**；
2. 直接双击新版 `语义摄像头.exe` 即可——配置与证据都在 `%LOCALAPPDATA%`，不会被覆盖；
3. 确认新版正常后，删除旧目录。

## 隐私

- 默认只监听本机回环地址，不对局域网暴露；
- 录像默认关闭；
- 日志与错误信息不打印 RTSP 密码或完整敏感地址；
- 不向任何外部服务上传画面、日志或配置。
