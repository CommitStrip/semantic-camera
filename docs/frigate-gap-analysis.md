# 语义摄像头 v2 vs Frigate 差距分析

> 2026-09-17 · 基于 Frigate 0.14+ 文档（docs.frigate.video）逐模块对照

---

## 一、我们真缺的（Frigate 有核心价值、我们没做）

### 1. 录像与回放（NVR 的本职）
Frigate：24/7 连续录像 + 事件片段导出 MP4 + 按相机/事件类型配置保留策略 + 时间线拖拽回放。
我们：**零录像**（隐私设计）。但"告警无凭据"是实际痛点——审查时只有文字没有画面。

**建议**：加告警前后 ±N 秒环形缓冲，告警时导出 mp4 片段，保留 7 天。不需要 24/7 全录。

### 2. 审查时间线 UI
Frigate：纵向时间线 + 低分辨率预览网格 + 悬停播放 + 自动标记已审查 + 按相机/对象筛选。
我们：工作台 HTML 是骨架（事件列表 + 相机状态），**没有时间线、没有预览、没有交互审查流**。

**建议**：这是工作台的 MVP 缺口——没这个用户看不到告警长什么样。

### 3. 多相机管理
Frigate：不限相机数 + Birdseye 动态组合视图 + 实时多路网格 + 按相机独立配置。
我们：cameras.json 支持多路，但**工作台只展示单相机状态**，没有多路切换和组合视图。

**建议**：值守页加多路画面网格（即使每路只有帧快照 + 告警横幅也够）。

### 4. MQTT 出口
Frigate：MQTT 是核心通信协议（事件/检测/状态全走 MQTT），深度集成 Home Assistant。
我们：只有 webhook 出口。

**建议**：加 MQTT 出口（paho-mqtt 纯 Python），打开自动化集成面。

### 5. 语义搜索 UI
Frigate：CLIP 缩略图嵌入 + 事件描述嵌入 → Explore 页面自然语言搜索 + Find Similar + 触发器。
我们：V-JEPA 嵌入已产出但**没有搜索界面**。

**建议**：事件工作台加"找相似"按钮（用嵌入余弦搜历史事件），不需要 CLIP 文本对齐。

### 6. 告警通知
Frigate：MQTT + Webhook + Home Assistant 通知 + Telegram（社区）。
我们：只有控制台横幅 + SQLite 记录。

**建议**：加 webhook 通知出口（POST 告警 JSON 到用户指定 URL）+ 可选邮件/Telegram。

## 二、设计上刻意不同的（不是缺失，是定位差异）

| Frigate 做法 | 我们的做法 | 为什么不同 |
|---|---|---|
| 检测为中心：检测到目标→录像→审查 | **语义为中心**：门控→检测→裁决→语义事件流 | 我们报警看的是语义规则（管理员定义什么危险），不是"检测到人就叫" |
| 封闭集检测（COCO 类） | **开放集**行为定义（admin 写什么算危险） | VLM 补充判定，不限于检测器类别 |
| 24/7 全录 | **不录视频**（隐私），告警时才抓帧 | 存储成本和隐私合规 |
| Coral TPU / GPU / OpenVINO | **onnxruntime**（CPU/GPU） | 降低部署门槛，不绑硬件 |
| 检测器自训练（Frigate+） | **不自训练**（数据先攒着） | 治理成本高，先攒数据后决定 |
| YAML 全量配置 | **JSON 场所档案**（两层 venue/camera） | 结构化更强，支持热加载 |

## 三、我们反而多做的（Frigate 没有的）

| 能力 | 说明 |
|---|---|
| **语义事件命名** | VLM 产出三层文本（短名/细节描述/rationale），事件可读可审计 |
| **V-JEPA 段嵌入** | 视频理解嵌入比对，同签名自命名零 VLM |
| **习惯化** | 重复场景调用趋零，token 消耗随使用衰减 |
| **自定义行为定义** | 管理员用自然语言定义"什么算危险"（开放集） |
| **预算制** | 仲裁/命名/理解分账，成本硬上限 |
| **模型双通道** | 本地 ollama / 云端 API 一键切换 |
| **四态裁决** | 宁可弃权不虚报（escalate 语义） |

## 四、行动建议（按性价比排序）

| 优先级 | 项 | 工作量 | 理由 |
|---|---|---|---|
| **P1** | 审查时间线 UI | 前端 1-2 天 | 没有这个用户看不到告警内容，工作台等于没有 |
| **P1** | 告警帧抓取+快照 | 后端 0.5 天 | 告警附带画面截图，审查有凭据 |
| **P2** | MQTT 出口 | 后端 0.5 天 | 打开自动化集成面（HA/NodeRed） |
| **P2** | 多相机值守网格 | 前端 1 天 | 多相机场景的管理基础 |
| **P3** | 语义搜索（找相似） | 后端+前端 1 天 | 嵌入已有，补 UI 查询 |
| **P3** | 事件导出 MP4 | 后端 0.5 天 | 审查取证需要 |
| **P4** | 配置热更新 | 后端 0.5 天 | 改规则不用重启 |
| **P4** | 认证（API key/session） | 后端 0.5 天 | 安全加固 |

## 五、不做的（边界即定位）

- 24/7 全量录像（存储成本+隐私合规，告警片段够了）
- 人脸识别/LPR/鸟类分类（超出场所语义值守定位）
- PTZ 自动跟踪（需要 PTZ 硬件）
- 音频检测（监控画面无声）
- Coral TPU（onnxruntime 够用）
