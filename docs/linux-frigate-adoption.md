# Linux NVR 版 · Frigate 借鉴边界

> 参考项目：<https://github.com/blakeblackshear/frigate>  
> 原则：借鉴成熟 NVR 的工程机制，不复制其产品中心；所有借鉴必须通过本项目的
> 管理员语义裁决、快慢分层和本地预算纪律。

## 保留不动的项目核心

1. **管理员定义什么算事**：区域、时间表、结构规则和可选语义模板决定告警，
   对象标签本身不自动等于危险。
2. **报警路径零慢层**：门控、检测、跟踪和确定性规则完成实时告警，JEPA/VLM
   只能事后增补命名与解释。
3. **JEPA 优先、VLM 只接新异**：已知模式自命名，重复理解成本趋零。
4. **事件上下文有界并及时归档**：不建立无限增长的对话或图片上下文。
5. **本地优先与显式外发**：录像、证据和模式默认只在 Linux NVR 本机。

## 借鉴并本地化的机制

| Frigate 成熟机制 | Linux NVR 版采用方式 | 本项目差异 |
|---|---|---|
| detect / record 流角色分离 | 配置增加低分辨率检测流与高分辨率录像流；允许同一地址兼任 | 不强制双码流，能力探测失败可退回单流 |
| 运动区域先筛、再做对象检测 | 保留现有 MotionGate → NanoDet 预算闸 | 门控参数以本项目实测为准，不照抄阈值 |
| 单相机活动聚合为 review item | 同一相机重叠活动合并成不可重叠审查段 | 审查段可包含管理员语义告警、普通检测或纯运动 |
| 录像先进入短期分段，再按策略保留 | 引入 cache → retention 两阶段；支持 continuous/motion/alert | 默认不启用24/7全量录像；告警优先保留 |
| Review 与完整录像分层 | 低带宽预览用于快速审查，点击进入原始录像 | 预览附带规则、语义说明和确定性证据 |
| 每个目标有生命周期和最佳帧 | 保存开始/更新/结束、区域进出、最高质量缩略图 | 生命周期服务于规则裁决，不成为告警真值本身 |
| 录像维护器和逐相机健康信息 | 每相机记录最后帧、最后分段、失败时长和重连次数 | 单相机故障不得阻塞其他相机或告警数据库 |
| 已保存录像可重放检测链 | 增加离线 replay，复现门控/检测/规则结果 | replay 必须固定配置快照、模型哈希和时间轴 |

## 明确不照搬

- 不把 `person`、`car` 等对象标签默认定义成告警；
- 不让审查项依赖录像成功，录像关闭或损坏时事件与告警仍须落库；
- 不直接复制 Frigate 的多进程、共享内存和庞大硬件后端矩阵；先保留当前
  单进程每相机线程，只有测量到隔离需求才拆进程；
- 不引入 go2rtc、Docker、Coral、Home Assistant 作为首版硬依赖；
- 不用 Frigate 的对象搜索取代 JEPA 模式习惯化；
- 不复制其 UI，只采用“审查段而非逐对象卡片”的信息组织原则；
- 不把24/7连续录像设为默认，用户必须显式选择保留模式和成本。

## Linux 落地顺序

### L1 事件与审查真值

- 事件拥有 `t_start`、`t_end`、状态和关闭原因；
- 同一相机活动聚合为不重叠审查段；
- 告警、检测、运动是审查段的三个证据等级，不互相冒充；
- 启动时关闭陈旧开放事件，迁移必须幂等。

### L2 录像证据链

- 配置区分 detect / record 流角色；
- 分段先写缓存，再由保留策略移动到正式目录；
- 告警前后缓冲、缩略图、审查段和录像时间轴使用同一绝对时间；
- 录像失败只降低证据完整度，不阻断告警。

### L3 可靠性与可观测性

- 连续取帧失败触发逐相机重连；
- `/api/stats` 暴露帧数、检测数、告警数、丢帧、重连、最后录像分段；
- 单相机、录像维护器和工作台故障相互隔离；
- 存储水位、孤儿媒体和陈旧缓存可检查、可修复。

### L4 可复现实验与发布

- 保存配置快照、模型哈希和原始时间范围；
- replay 对同一录像重跑快路径，输出可比较事件；
- 两路以上真实 RTSP 运行24小时；
- 告警时延使用真实源时间戳，分别报告 P50/P95/P99。

## 完成定义

只有同时具备代码、自动化测试、Linux 主入口接线和真实设备证据，才能标为
“Linux 已交付”。来自 Frigate 的设计启发或独立模块实现不得越级计入完成状态。
