# Linux NVR 发布实施计划

> 产品：语义摄像头 Linux NVR 版  
> 唯一入口：`python -m scam.linux_nvr`  
> 目标：在常开 Linux 主机上，把监控流转化为可裁决、可审查、可回放的场所语义事件；管理员规则触发的告警 P95 不超过 1 秒，重复场景的理解成本趋近于零，默认数据不出本机。

本计划是 Linux 版从当前实现走到可发布状态的执行合同。设计边界以
[`设计稿-总集.md`](../设计稿-总集.md) 为准；Frigate 只提供工程理念，采用与不采用的边界见
[`linux-frigate-adoption.md`](linux-frigate-adoption.md)。

## 1. 不可偏移的产品约束

1. 告警只来自管理员定义的区域、类别、时间与滞留规则；检测标签本身不是告警。
2. 快系统不等待录像、V-JEPA、VLM、命名或外部通知；这些能力失败时，结构化告警仍须落库。
3. 每个事件有独立、有界上下文，关闭即归档；不能把长期运行历史堆进一个模型上下文。
4. 重复模式先查本地档案，只有新异事件才进入预算受控的慢理解。
5. 默认本地处理、SQLite 持久化、工作台仅回环监听；云通道必须由管理员显式开启。
6. Linux 和 Win11 分别验收。共享模块通过测试不等于 Linux 主链接线，更不等于 Linux 真机可发布。

## 2. 证据等级

所有功能只能使用以下最高已证实等级，禁止跨级表述：

| 等级 | 含义 | 最低证据 |
|---|---|---|
| 设计 | 契约和边界已写清 | 设计文档与验收条目 |
| 模块 | 独立实现成立 | 单元测试或确定性回放 |
| 接线 | Linux 默认入口实际经过该模块 | Linux 入口集成测试、配置与状态可见 |
| 主机验证 | 在目标 Linux 主机和真实 RTSP 上成立 | 命令、日志、数据库、录像等原始产物 |
| 质量验证 | 指标达到发布阈值 | 固定数据集、统计报告、24 小时浸泡与隐私审计 |

自动化测试不能替代真实 Linux、真实相机、真实时间戳和长期运行证据。

进入真实主机验收前，可先保存只读环境基线：

```bash
python -m scam.linux_host_probe > linux-host-preflight.json
```

该命令不执行外部程序、不安装依赖、不控制服务也不访问RTSP；它只记录平台、Python及
ffmpeg/ffprobe/systemctl的路径可发现性。两个总门禁字段固定为空，命令存在不等于版本
兼容、服务正常或主机验收通过。

## 3. 里程碑与退出条件

### L0 — 双产品边界与执行基线

交付物：

- Linux 独立入口、默认数据目录、安装脚本与 systemd 服务；
- 共享核心与平台档案分离；
- Linux 上下文记录本与公开路线图分离，内部记录不进入 GitHub；
- CI 分别验证共享契约与产品入口。

退出条件：部署文档不再引用兼容入口；Win11 证据不会被计入 Linux 状态。

### L1 — 事件与审查真值

交付物：

- 告警事件具有开始、结束与结束原因；进区、持续、离区、重入、跨区状态可确定性复现；
- 同一相机同一时间最多一个开放审查段，多目标活动聚合为一段；
- 审查段区分普通检测和管理员规则告警，并保留目标、区域和告警数；
- 数据库迁移幂等，崩溃重启后开放事件和审查段被保守闭合而非删除；
- `/api/events`、`/api/review`、`/api/stats` 能读取生命周期和降级状态；
- 录像关闭或失败不阻塞告警落库。

退出条件：模块与 Linux 接线测试全绿；存量库迁移、重启恢复、重叠目标聚合、录像失败隔离均有回归测试。

### L2 — 录像证据链

交付物：

- 每相机区分 detect 与 record 输入角色，复用连接的边界明确；
- ffmpeg 流拷贝分段录像进入 Linux 主链，天数与容量双闸生效；
- 告警前后片段可导出、可播放，并能追溯事件、相机、源时间范围和配置快照；
- 录像进程失败、磁盘满、片段损坏均产生可读状态，不影响快告警；
- 默认录像策略遵守设计稿：不把 24/7 全量录像偷渡成产品默认。

退出条件：合成源自动化测试成立，并在目标 Linux 主机上用真实 RTSP 留下可播放片段与故障隔离证据。

### L3 — 常驻可靠性与可观测性

交付物：

- 每相机断流看门狗、指数退避、恢复计数与最近错误；
- 相机、检测器、录像器、存储、慢系统和出口分别报告健康，单路故障不拖垮其他相机；
- systemd 启停、崩溃拉起、优雅停机和数据库恢复可验证；
- 资源指标覆盖 CPU、内存、句柄、线程、磁盘增长与队列水位；
- webhook/MQTT 若进入首发，必须有有界队列、超时、重试上限和秘密脱敏；否则明确延后。

退出条件：真实断流 30 秒内进入恢复流程，恢复后继续形成事件；两路真实 RTSP 可并行值守且互不拖垮。

#### 浸泡原始证据采集

目标主机启动 NVR 后，用独立终端运行：

```bash
python -m scam.linux_soak \
  --base-url http://127.0.0.1:8765 \
  --output-dir storage/soak/$(date -u +%Y%m%dT%H%M%SZ) \
  --duration-seconds 86400 \
  --interval-seconds 30
```

每次运行创建全新目录，包含主机/运行参数清单、逐次`/api/health`与`/api/stats`
原始NDJSON、滚动SHA-256链和结束摘要。默认只允许回环地址；远程主机优先用SSH隧道，
确需非回环目标时必须显式`--allow-non-loopback`。采集器会如实记录HTTP、JSON和超时
失败，但摘要的`release_gate_passed`固定为空——采满24小时不自动等于门禁通过，仍须
复核真实RTSP路数、断流恢复、资源平台期、systemd日志和失败阈值。长跑汇总只保留
有界计数，不把全部样本再次常驻内存；相机状态取自`watchdog.cameras`，顶层
`cameras`的门控比例不会被误记为online/stalled/recovering状态。
收到`SIGINT`或`SIGTERM`时，采集器在最多约1秒内结束等待、落盘带
`termination_reason`的部分摘要并返回非零退出码；部分运行不会被误标为完成24小时。

采集结束后先离线校验证据包结构与滚动哈希链：

```bash
python -m scam.linux_soak_verify --output-dir storage/soak/<run-id>
```

验证器完整时退出0，损坏、缺失或不安全输入时退出非零并输出机器可读JSON。它只证明
manifest、逐条样本和summary之间的结构/哈希一致性；输出中的
`release_gate_passed`固定为空，不能替代真实Linux主机、两路RTSP、24小时持续运行、
资源平台期、断流恢复和systemd日志复核。

### L4 — 可回放、质量闭环与发布

交付物：

- 固定录像、场所配置、模型哈希和软件版本可重放检测—裁决—事件链；
- 使用真实源时间戳统计告警送达 P50/P95/P99，不以处理循环时间冒充；
- 标注集覆盖昼夜、遮挡、进出、滞留、跨区和无目标场景，报告误报与漏报；
- 报告重复模式命中率、VLM 调用曲线、降级比例与单位相机成本；
- 本地模式网络审计证明无帧或敏感载荷外发；
- 安装、升级、回滚、备份恢复和已知限制文档完成。

退出条件：下列发布门禁全部具备可复核产物，不留“计划中”条目。

## 4. 发布门禁

| 门禁 | 阈值 | 必须保存的证据 |
|---|---|---|
| 快 | 管理员规则条件满足到告警送达 P95 ≤ 1 秒，同时报告 P50/P99 | 源时间戳、送达时间戳、原始样本与统计脚本输出 |
| 准 | 首发标注集上的误报率 < 5%，并单列漏报率 | 数据集版本、标注规则、混淆表、失败样例 |
| 省 | 重复场景的 VLM 调用率随模式稳定明显下降 | 按时间/模式的调用计数和命中曲线 |
| 稳 | 至少两路真实 RTSP 连续运行 24 小时，无进程崩溃，内存与句柄进入平台期 | systemd 日志、健康快照、资源曲线、断流恢复记录 |
| 证 | 告警关联的录像/缩略图/配置/模型版本可追溯且录像可播放 | 事件导出包、哈希、播放器或 ffprobe 结果 |
| 私 | 本地模式无公网帧上传，工作台默认只绑定回环 | 网络抓取/连接审计、启动参数、配置快照 |
| 运 | 干净 Linux 安装、升级、重启恢复、容量闸和备份恢复均通过 | 主机信息、完整命令、退出码、日志与恢复前后校验 |

## 5. 发布候选与正式发布定义

满足 L0–L4 的模块和接线条件、所有公开自动化测试通过、没有已知数据损坏或隐私高风险问题，才可生成发布候选（RC）。

RC 必须在干净的受支持 Linux 主机上完成安装，并完成两路真实 RTSP 的 24 小时浸泡。只有发布门禁表全部通过，产物可由另一人复核，且文档中的限制与实际行为一致，才能标记正式发布。缺少真实主机、真实相机或 24 小时证据时，最高只能称为“模块/接线完成”，不能称为可发布。

## 6. 实施顺序与风险控制

1. 先建立事件/审查真值，再让录像和慢理解引用它，避免多个互相冲突的事件定义。
2. 录像以旁路证据能力接入；任何录像故障测试都必须同时断言告警仍落库。
3. 可观测性先于长期浸泡，否则 24 小时运行无法解释失败原因。
4. 回放先固定输入、配置和模型哈希，再谈准确率，避免不可复现实验。
5. 真机阶段如无 Linux 主机或 RTSP，继续完成可离线验证的工作，但把主机与质量门禁明确保持为未完成。

主要风险及控制：

| 风险 | 控制 |
|---|---|
| 把检测活动等同告警 | 审查段分 `detection`/`alert`，只有管理员规则可升级为 `alert` |
| 录像耦合快路径 | 异步旁路、失败注入、告警独立落库断言 |
| 重启丢失审计历史 | 开放状态保守闭合并记录 `startup-recovery`，不删除旧记录 |
| 测试时延冒充真实时延 | 接收源时间戳贯穿全链，质量门禁只接受真实源时间 |
| 多相机故障扩散 | 每相机生命周期、健康和重试隔离 |
| 借鉴变成照搬 | 每项实现同时对照产品设计与 Frigate 借鉴边界，冲突时产品设计优先 |
