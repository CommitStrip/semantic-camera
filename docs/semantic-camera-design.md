# 语义摄像头（Semantic Camera）平台设计

*v2.5 · 2026-09-10 · 本仓为库系主线；v1（反无人机单场景判别自动化）已在前身仓落地；v2 吸收第一轮外部架构审查（§0.1–0.2、§4 v3 schema、§14 证据事件）；v2.2 吸收第二轮审查（P0 fail-closed 模式选择、证据溯源字段、自训练默认关闭、红线措辞修正）；v2.3 收录 Vision Agents 调研结论与借鉴边界（§19，含告警出口确定性主链 §14、DetectorProvider 契约 §16）；v2.4 P1-①② 落地（restricted-area 真实化、资产单源化，§17 M1.8）；v2.5 M2 vus 桥落地（§8）*

---

## 0. 一句话定位

> **语义摄像头 = NVR 标准件之上的场所语义判别层**：端侧实时流水线（门控 → 检测 → 跟踪 → 判别 → 告警）+ 按场所加载的模式包 + 全自动判别闭环 + vus 慢脑仲裁。对外口径：**A budget-aware, mode-configurable edge vision event runtime**（预算受控、模式可配置的端侧视觉事件运行时）。
>
> 设计红线（v2.2 修订措辞）：**判别流水线全自动运行、无人工判定环节**——判别不等人；但**"自动理解 ≠ 自动执行一切"**：人工复核不阻塞实时管线，高影响外部效果（执行层）是否需要人工确认由 Effect Policy 决定（`action_recommended: review` 即为复核消费者预留）。第二红线：**成本有硬上限**（预算制）。第三条（平台成立判据）：**新增场所不改核心逻辑代码**——领域数据进注册表、核心源码洁净度由单测把守。
>
> 模式选择 **fail-closed**（v2.2 P0 修复）：未知 `?mode=` 返回 null 并拒绝布防，**严禁静默回退到其他场所**——选错模式比配置非法更危险（限制区域摄像头静默跑反无人机模型 = 表面在布防、实际无人检测）。

## 0.1 平台成立的验收标准（外部审查采纳）

> "能不能在不修改核心的情况下，同时支持反无人机和另一个完全不同的场所模式？能做到，它就是平台；做不到，它只是把一个反无人机 Demo 换成了更大的名字。"

验收项（全部有对应单测，CI 强制）：

1. **双模式端到端**：同一套核心组件（跟踪/门控/裁决/仲裁队列/证据事件）以 `airfield` 与 `restricted-area` 两个模式包驱动跑通 检出→跟踪→确认→裁决→证据事件，不改核心代码；
2. **两包差异必须足够大**：检测引擎（onnx vs mock）、检测类别、判别头有无、布防时间表有无——抽象不是为单一场景量身定制；
3. **核心源码洁净度**：`core.js` 与 `index.html` 内联脚本不得出现领域类别词（正则元测试）。**洁净度只证明文本洁净，不证明抽象正确**——隐式领域假设（二分类判别、单告警类别、固定实际尺寸、单目标事件）的真正证伪靠第三种事件形态（烟火/人群/遗留物，P2）；
4. **检测器可插拔**：`detector.engine = 'onnx' | 'mock'`，mock 为确定性时间线脚本（CI 确定性 + 无模型演示）；
5. **判别头可选**：`discriminator: null` 时检测器权威（显式降级路径，四态语义与判别路径一致）；
6. **无模型时明确降级**：设计态模式包标 `status: 'design'`，UI 显示"设计态(mock 演示)"，不宣称可用。

`restricted-area`（限制区域闯入：人员类别、夜间布防、无判别头）即第二个模式包——核心抽象已由 CI 验证；真实人员检测模型接入前以 mock 运行并诚实标注。

## 0.2 宣传口径纪律（防"语义摄像头"过度宣传）

**不宣称**：自动理解所有场景 / 无需数据适应新场所 / 自动进化后越来越准 / 通用异常检测 / 零误报 / 人类级语义理解 / **"零代码接入新场所"**（准确说法：**新增场所不改核心逻辑代码**——仍需在注册表加数据并重新部署）。
**只宣称实测过的**：探针离线精度、CI 测试、WHEP 验证；其余一律"待回填/设计态/路线图"。当前算法（帧差门控 + 检测模型 + 跟踪 + 特征探针 + 阈值裁决）的诚实定位是"**可配置事件摄像头 + 场所判别头**"；更高语义能力由后续里程碑（开放集、时空规则、仲裁回灌）逐步兑现，兑现前不预支宣称。

## 1. 家族定位：为什么独立建仓、为什么它是重点

```
┌────────────────────────────────────────────────────────────┐
│  semantic-camera（本仓，主线旗舰）                          │
│  场所语义监控平台：边缘核心 + 模式包 + 时空规则 + vus 桥     │
└───────┬───────────────────────────────┬────────────────────┘
        │ 依赖引擎                       │ 同源演化
┌───────▼──────────────┐   ┌────────────▼─────────────────┐
│  vus 通用视频理解核心 │   │  anti-drone-monitor（前身）   │
│  快慢双系统/成本上限  │   │  反无人机单场景演示，冻结维护  │
└───────┬──────────────┘   └──────────────────────────────┘
        │ 设计叙事延伸
┌───────▼──────────────┐
│  rvs 机器人增量层     │
└──────────────────────┘
```

- **为什么独立建仓**：anti-drone-monitor 的仓库名、历史与叙事都绑定单一场景；语义摄像头是库系的**产品主线**，应有独立的版本节奏、README 叙事与 issue/里程碑管理。前身仓冻结为演示与出处的锚点，不做破坏性改动。
- **边界**：本仓**不是** vus 的重写——vus 继续做通用视频→LLM 压缩引擎；本仓消费其架构与（M2 起）其慢脑能力。本仓也**不与 NVR 标准件竞争**感知层（运动/人形检测是标准件），做的是标准件之上"判得对、报得准、成本可控"的增量。
- **护城河表述**：零训练门控 + 触发式慎思 + 预算硬上限 + 全自动判别闭环 + 场所模式包。机制层全是已知轮子，价值在集成质量与场景收口。

## 3. 总体架构：三层拓扑

```
┌─ 场所（Venue）────────────────────────────────────────────┐
│  VenueController（M4 落地，单相机时退化为主循环内联）       │
│  · 模式包装载与校验（fail-closed）  · 跨相机预算分配        │
│  · 时空规则引擎（zones/schedule/复合事件）                  │
│  · 告警出口路由（HUD/快照/webhook）                         │
└───────┬────────────────────────────────────────────────────┘
        │ 每相机一个
┌───────▼────────────────────────────────────────────────────┐
│  EdgeCore（本仓 web/ 核心，浏览器/WebView/Node 均可跑）     │
│  T0 帧差反射(ms) → T1 触发式检测(400ms/巡检5s)             │
│  → T1.5 JEPA 四态判别(确认目标,30s节流,懒加载)             │
│  → 告警语义(裁决+布防时间表) → 全量遥测                     │
└───────┬────────────────────────────────────────────────────┘
        │ 灰区案件（预算内）
┌───────▼────────────────────────────────────────────────────┐
│  vus 桥（M2）：本地 WS 服务 → vus 慢脑 VLM 仲裁             │
```

单相机阶段 VenueController 的职责内联在 EdgeCore 主循环（现状即跑）；多相机阶段抽出，预算按"场所/小时"而非"每路/小时"分配，触发式与节流机制原样复用。

## 4. 场所模式包 v3（核心抽象）

**模式包 = 纯数据 + 校验器**：换场所不改流水线代码。模式包注册表在 `web/mode-packs.js`——**全仓领域词（类别/模型/阈值）的唯一居所**，有源码洁净度元测试把守；校验器 `validatePack()` 在 `web/core.js`（领域无关）。schema 全貌：

```js
{
  id: 'airfield', name: '净空防黑飞', version: 1,
  status: undefined,                       // 'design' = 设计态（UI 显式标注，不宣称可用）
  detector: {                              // 检测器（可插拔，见 §16）
    engine: 'onnx',                        // 'onnx' | 'mock'（确定性时间线脚本）
    model: './yolov8s-drone.onnx',         // onnx 引擎必填；mock 可省
    classes: ['drone'],                    // 检测类别（核心不感知）
    confThresh: 0.25, inputSize: 640,
    sizeByClass: { drone: 0.35 }, defaultSizeM: 0.35,   // 估距实际尺寸(米)
    // mockScript: [...]                   // mock 引擎的确定性检出时间线
  },
  discriminator: {                         // 判别头；null = 无判别器（检测器权威，显式降级）
    classes: ['bird', 'drone'],            // [负类, 正类]，探针输出 P(正类)
    probe: './jepa_probe_init.json',
    alertConf: 0.80,
  },
  detectorAlertConf: 0.60,                 // 判别未出/无判别器时，检测器权威阈值（防漏报）
  alertCls: 'drone',
  schedule: [{from:'22:00', to:'06:00'}],  // 布防时间表（可跨零点；缺省 7×24，见 §6）
  // zones: [...],        // M3：多边形区域规则（净空区/禁入区/计数线）
  // composite: [...],    // M3：复合事件（A 后 B 于 T 内 / 滞留 / 计数 / 方向）
  // sinks: [...],        // M5：告警出口（hud/snapshot/webhook/push）
  arb: { budgetPerHour: 20, ttlMs: 15000 },          // 仲裁预算 + 轨迹去重
  selfTrain: { minConf:0.90, marginRatio:0.80, cooldownMs:60000, lr:0.05 },  // 无判别头时必须显式 null
}
```

- **配置校验 fail-closed**：`validatePack()` 在装载时校验全部不变量（检测引擎/类别、判别头二类与闸门区间、alertCls 可判别性、自训练严于告警闸门、时间表格式等），不合法则**拒绝布防**并明确报错——坏配置宁可不起流水线，不带病上线。
- **检测置信 ≠ 判别置信**：两条路径的闸门分开（`detectorAlertConf` vs `discriminator.alertConf`），裁决结果带 `via` 来源标记，单个模型分数不会被一路传成处置结论（§14 证据事件里两者分立记录）。
- 首波场所目录：净空防黑飞（✅ 完整落地）→ 限制区域闯入（✅ 真实模型 NanoDet-Plus@416 + zone 规则）→ 油库烟火（烟/雾判别，误报抑制杀手场景，M3）→ 工地合规（M3）→ 校园周界（M3）→ 养殖驱避（M5）。一机多包（一台相机同时跑周界+烟火两包）在 VenueController 设计时支持，模式包保持纯函数语义。

**v3.1 增补（P1-①② 落地，2026-09-10）**：
- detector 增加 `head`（解码器注册键，`HEAD_DECODERS`：yolo8head/nanodethead/mock）、`keepIndices`/`numClasses`（多类模型保留子集，如 COCO person=0）、`strides`/`regBins`（GFL 分布回归参数）；
- `zones` 从设计转落地：进入区域 + 滞留达标（dwellMs）才升级告警（`reason: zone-intrusion`），区外降级 record（`outside-zone`）——区域引擎 `ZoneEngine`/`applyZonePolicy` 为 core 纯函数，单测覆盖；
- restricted-area 升级为**真实模型模式包**：NanoDet-Plus-m-1.5x@416（Apache-2.0，官方 ONNX 9.89MB），真实街景抽帧实测 person 7~58 检出/帧、CPU 23-24ms/帧（选型/淘汰证据与解码契约见 docs/model-selection.md）。

## 5. 判别体系（全自动闭环）

### 5.1 四态裁决（已落地，双路径）

探针输出 P(正类) → `alert`（目标侧高置信，告警）/ `escalate`（目标侧置信不足，**弃权待仲裁不虚报**）/ `clear`（判明非目标）/ `suppress`（静默）。四态语义在两条路径上一致：

- **判别路径**（有判别头）：`decideDiscriminated(P)`，闸门 = `discriminator.alertConf`；
- **检测器权威路径**（无判别头 / 判别未出——防漏报）：`decideDetector(cls, conf)`，闸门 = `detectorAlertConf`；裁决带 `via` 来源标记，检测置信与判别置信不混用。

布防时间表之外（§6），alert 降级为记录、escalate 不占仲裁预算。

### 5.2 开放集拒绝（M3，本设计补强）

现有判别是**封闭世界**假设：世界只有鸟和无人机。真实场景有"都不是"（气球/风筝/飞机/塑料袋），硬塞进二类比只会制造高置信错误。补强：

- 探针增加**拒识通道**：到两类质心的最小距离超过标定阈值（或 kNN 距离/能量分数超阈）→ 判 `unknown`，一律走 `escalate`；
- 阈值来自模式包发布时的**留出集标定**（按召回-误报曲线选工作点），随探针版本发布，不拍脑袋；
- VLM 仲裁天然是开放词汇的——`unknown` 案件是它最有价值的输入，也是新类别数据的来源（发现即登记进场所词表）。

### 5.3 漂移监控（M4）

相机被移动/对焦失准/昼夜切换/天气突变都会让门控与判别同时劣化。治理：

- 门控侧：运动占比 `lastRatio` 已逐帧采集，滚动统计其分布，偏移超带 → 遥测打 `drift` 事件提示重校准；
- 判别侧：escalate 率与 alert 后被仲裁推翻率（M2 起可得）双指标滚动监控，超带自动降级为"仅检测"模式并提示；
- 原则：**判别置信下降必须可观测**，不允许静默劣化。

## 6. 时空语义引擎（场所语义的主体）

类别告警只是语义的最浅层；场所语义的主体是**时空规则**，全部做成模式包数据。布防时间表、多边形 zone+滞留、**越线（带方向）+ 区域占驻计数（countGte）**已落地，其余按里程碑推进：

| 规则类型 | 数据形态 | 场所示例 |
|---|---|---|
| 布防时间表 `schedule` | `{from,to}` 窗口数组，支持跨零点（✅ 已落地） | 校园周界 22:00–06:00；工地吊臂区全天 |
| 区域 `zones` | 归一化多边形 + 类别 + 滞留 `dwellMs` + 占驻计数 `countGte`（✅ 已落地：进区+滞留达标升级 `zone-intrusion`，人数不足降级 `zone-count`，区外降级 record） | 净空区禁入无人机；围栏区域闯入；人群聚集 |
| 警戒线 `rules.lines` | 线段 + 方向 `any/AB/BA`（✅ 已落地：轨迹历史扫描 segIntersect，同线冷却防抖动） | 大门越线单向告警；围栏双向翻越 |
| 区域 `zones` | 归一化多边形 + 触发类别 + 方向 | 净空区禁入无人机；围栏单向越线 |
| 滞留 `dwell` | 类别 + 区域 + 时长 | 无人车前滞留 >60s |
| 计数/聚集 `count` | 类别 + 区域 + 阈值 + 窗口 | 鸟群 ≥5 只 30s（鸟击预警）；人群聚集 |
| 复合事件 `composite` | 事件 A 后事件 B 于 T 内 | 检出烟火后 10s 内有人员接近 |

规则求值是纯函数（可单测），输入 = 轨迹流 + 判决流，输出 = 告警事件。**规则即数据**，与模式包同源同校验。

## 7. 多相机与资源调度（M4）

- 单盒 N 路时，T0 门控逐路常开（廉价），T1 检测与 T1.5 判别是**全局共享的稀缺资源**：按场所预算排队（触发式天然削峰），峰值按"告警密度优先、巡回兜底"调度；
- 每场所成本上限不变：仲裁预算是场所级而非路级；单飞合并升级为跨路去重（同一物理目标跨相机只裁一次）；
- wasm 秒级单次推理意味着单进程吞吐有天花板：M4 给出 N 路实测吞吐表后再定多进程/原生运行时（Node worker）路线，**先实测后设计**，不预写架构。

## 8. vus 桥协议（M2，✅ 已落地 bridge/）

本地 WS 服务（与 MediaMTX 网关同级的本地件，默认只绑内网，`bridge/server.py` + `websockets`）。

**已实现（2026-09-10）**：

- **令牌鉴权**：hello 握手 5s 超时，不匹配 4401 拒绝（实测 ✓）；
- **仲裁器注册表（可插拔）**：`abstain`（诚实弃权——桥通但无慢脑时不产伪标签）/ `clip`（本地 CLIP 零样本：完整 CLIPModel ONNX 复用 vus models 目录资产，与边缘 DINOv2 探针**异族独立**；语义抽检 person 0.90 / dog 0.98；端到端裁决 570ms）/ `ollama`（vus 慢脑同款路线，主机经 `validate_http_base` 校验：仅环回+显式允许表，http.client 直连不跟随重定向）；
- **案件归档**：输入+裁决+灰区裁剪帧追加 JSONL（M5 复训语料；`archiveCrops` 可关）；
- **边缘侧 `BridgeLink` 纯逻辑链路**（core.js，单测覆盖）：指数退避重连、requestId 关联、超时/断线/拥塞三态拒绝 → 上层降级边缘自治（灰区保持弃权，绝不虚报）；
- **回灌开关**：`arbFeedback` 模式包标志，独立于自训练开关；预算受仲裁队列上限约束。

本地 WS 服务（与 MediaMTX 网关同级的本地件，默认只绑内网）：

```
EdgeCore → 桥：{type:'arb-request', trackId, packId, task:'main',
                cropJpeg(base64, ≤224px), scores:{logreg, protoMargin},
                ts, cameraId}
桥 → EdgeCore：{type:'arb-verdict', trackId, label, conf, vus:{model, latencyMs}}
```

- **去重与预算在边缘侧已实现**（ArbitrationQueue），桥只做转发，无状态；
- 背压：桥忙时返回 `busy`，边缘按 `budget` 语义降级（保持弃权，不虚报）；
- 超时 30s 无回 → 案件保持 `escalate` 挂牌，落遥测离线消费；
- **降级即自治**：桥不可达时边缘全功能自治运行（判别/裁决/自训练都不依赖桥），桥只增强不阻断；
- 鉴权：本地共享令牌（配置文件），WS 握手校验；
- 归档：每案件输入输出落 JSONL（桥侧），是 §11 复训语料的来源。

## 8.1 场景自识别（✅ 已落地，2026-09-10）

模式包从"部署参数"升级为**摄像头运行时状态**：无场景时跑通用人员引导包（观察模式），首个确认事件触发慢脑识别场所类型，高置信自动布防，用户随时人工改配。

**状态机**：`unidentified（观察模式）→ identifying → identified(auto|manual)` / `failed（待人工选择）`。优先级：**人工指定 > 自动识别 > 未识别**，人工指定后永不自动覆盖（除非点"重新识别"）。

**机制**：

1. **观察态**（引导包 `_bootstrap` = 通用人员检测）：检测/跟踪/证据事件照常，告警由场景层全抑制（`applySceneGate`）——什么都不丢，也不虚报；
2. **采样**：首个确认目标触发，攒 1 张宽帧 + 最多 3 份裁剪帧（3 分钟窗口）；
3. **识别**：经 vus 桥 `scene-identify` 消息送慢脑——**双通道**：CLIP 零样本（各模式包的场所描述文本为 prompt，离线兜底）+ ollama VLM（宽帧+裁剪帧+目录文本，质量路线）；桥断时停在观察态，人工手选路径不依赖桥；
4. **收口**：`selectPackFromVerdict`——命中已注册包且 conf ≥ 0.85 → 自动切换并布防（横幅可改）；conf 不足 → 标记 failed 并预选建议项待人工确认；未知 packId = 无效裁决（fail-closed）；
5. **人工覆盖**：场景下拉框随时切换（运行时热切换：重建 policy/arb/zoneEngine/detector/jepa，轨迹重置），持久化 localStorage 按 cameraId 生效。

**红线兼容**：识别异步跑在桥上不阻塞实时管线（判别红线）；每摄像头一次 VLM 调用有界（成本红线）；闭集选择/开放集起草都只产数据、过 validatePack（平台红线）。模式选择 fail-closed 语义升级：未知 `?mode=` 与识别失败都进观察模式（仅记录），绝不静默跑别家告警。

**v2（开放集起草）**：VLM 对无包画面起草新场景定义（类名/布防建议/zone 提示）→ validatePack 校验 → 人工编辑确认 → 沉淀为新模式包。前置：zone 绘制 UI（M3）。



## 9. 可靠性工程

- **健康监控**（M4）：流断/帧冻结/镜头遮挡（门控长期全黑或全静）/过曝，检测到即遥测 `health` 事件并在 HUD 挂牌——摄像头自己的病不能伪装成"场所安全"；
- **降级链**（每级可观测）：判别不可用 → 检测器权威（防漏报）；桥不可用 → 边缘自治（灰区弃权）；门控异常 → 提高巡检频率并告警自身状态；
- **fail-open 与 fail-closed 的分界**（明确写死）：**安全告警语义 fail-open**（判别未出前检测器权威，宁可误报不可漏报——误报有裁决层兜，漏报没有）；**配置与模型装载 fail-closed**（坏配置/坏探针拒绝布防）。两条红线不混用。
- 真机端到端帧率/延迟实测待回填（遥测已逐帧采集 `detMs/trackMs/motionRatio`，导出即为数据）；int8 量化结论沿用前身仓实测：现 opset12 导出量化后检出归零，需以现代 opset 重导 yolov8n，量化工具自带任务级闸门防静默失效。

## 10. 隐私与合规（产品级卖点，不是脚注）

- **默认视频不出场**：检测/判别/裁决全部端侧；唯一上云通道是 M2 桥的**灰区小裁剪图**（≤224px、无附加元数据、场所可配置关闭——关闭后灰区永远弃权，不虚报）；
- 上传内容**不含全帧**、不含音频；桥与 vus 部署在场内/自有算力，不经过第三方；
- 数据保留：遥测与仲裁档案保留期可配置（缺省 30 天），到期清理；导出即审计（CSV/JSON/JSONL 全链路留痕：检出→裁决→仲裁→自训练每步可回放）；
- 人形相关模式包（工地/校园）启用前必须给出场所告示与数据主体回应通道的部署清单——合规能力进模式包 checklist，不是口头承诺；
- 对齐个保法/GDPR 的最小化原则：目的限定（告警）、最小范围（裁剪）、期限（可配）。

## 11. 持续学习治理（自动化的代价是必须治理自动化）

自训练与仲裁回灌都是无监督写入探针，必须有防线。**v2.2 裁决：自训练默认关闭（`selfTrain.enabled:false`）**——logreg 头与原型距离都来自同一特征空间，并非独立证据，域外目标可能同时骗过两者并持续漂移；在治理栈完备前不得默认在线修改判别头：

0. **治理前置（当前未完备，故默认关闭）**：冻结 golden set + 每次更新前后回归评测 + 最大单日更新量 + 版本化 checkpoint + 自动回滚 + 漂移指标 + 开放集拒识 + 模型更新审计事件——全部就绪（M5）后按场所显式开启；
1. **入口闸门**（开启后生效）：双信号一致（logreg + 原型距离）+ 置信 ≥0.90 + 冷却 60s/轨迹（已落地；双信号仅作必要条件而非独立证明）；
2. **学习状态按场所/模式隔离**（已落地）：持久化键 = `jepa_probe_v2:<modeId>`——机场的鸟类外观、天空背景与光照形成的伪标签不得污染另一个机场或另一个场所；后续多相机阶段扩展为 `site_id/camera_id/mode_id/model_version` 全键隔离（§7）；
3. **类平衡**：两类样本计数差超带（如 3:1）暂停自训练偏向类，防探针被高频类拖走；
4. **遗忘防线**：自训练后探针在**冻结校准集**（模式包发布时随带，每类 ≥30 样本）上的精度不得跌破发布值 −2pp，跌破即自动回滚到上一版本（探针版本号 + localStorage 双版本槽）；
5. **影子晋升**（M5）：新探针（离线复训产物/大批量回灌产物）先影子运行只记不发，跑满 ≥48h 且指标不劣才晋升；
6. **全面可撤销**：重置学习 = 回初始权重（已落地），版本回滚 = 回上一稳定版。

## 12. 评测体系（结论只认实测）

- **每模式包一份基准集**：发布时冻结（图像 + 标注 + 划分），随仓库带评测脚本；
- **指标**：告警精确率/召回率、escalate 率（弃权率是特性不是失败）、仲裁预算命中率、每路每天推理次数与耗时、自训练后校准集精度；
- **CI 闸门**：判别相关 PR 必须附基准集指标，核心指标回退 >1pp 拒绝合入（沿用前身仓"任务级闸门防静默失效"的路线）；
- 头版只填实测数字，未测项明确标"待回填"，不预填设计值。

## 13. 安全

- 本地网关与桥默认只绑内网接口，WS/HTTP 帧鉴权令牌必填（无默认口令）；

## 14. 证据事件与告警出口

**证据事件 `sc.evidence/v1`（已落地）**：从"帧"到"有证据的事件"——机器（Agent/工作流/审计）消费的版本化信封，而非裸视频或简单 motion 标志。每次确认目标产出：

```json
{
  "schema": "sc.evidence/v1",
  "event_id": "cam:restricted-area:alert:17:1725856420000",
  "kind": "alert",
  "time": { "source": 12.5, "processed": "2026-09-09T02:32:10.000Z" },
  "mode": { "id": "restricted-area", "version": 1, "hash": "fnv1a:0a9f1c2b" },
  "policy_version": "four-state/2",
  "track": { "id": 17, "cls": "person", "conf": 0.82, "bbox": [...], "dist": 6.1 },
  "belief": { "label": "person", "conf": 0.82, "probeVersion": 3 },
  "decision": { "action": "alert", "via": "detector", "armed": true, "reason": "detector-authority" },
  "models": { "detector": { "engine": "onnx", "name": "...", "sha256": "…" }, "discriminator": "…", "probeState": "jepa_probe_v2:…" },
  "evidence": { "videoTs": 12.5, "frame": 375, "cropJpeg": "data:image/jpeg;...", "cropSha256": "sha256:…" },
  "action_recommended": "notify"
}
```

溯源字段（v2.2 补齐）：**event_id**（camera:mode:kind:track:毫秒，去重/重放/外部告警幂等）、**双时间戳**（`time.source`=视频源时间 / `time.processed`=本地处理完成——RTSP 抖动与端到端延迟可算）、**mode.hash**（模式包内容指纹，键序无关 FNV-1a——证明当时生效的阈值快照；非加密哈希，防漂移不防篡改）、**policy_version**（模型没变裁决逻辑也可能变）、**models.detector.sha256**（文件名不是版本，哈希才是；加载后后台计算补齐）、**evidence.cropSha256**（证据内容哈希，防替换，异步尽力补齐）、**evidence.preRoll**（告警前因帧环：~500ms/帧 × ≤12 帧 ≈ 6s 前因，`FrameRing` 环形缓冲——"frame-before" 证据落地）。

要点：**检测置信（track.conf）与判别置信（belief.conf）分立**，decision 带裁决来源与布防状态，告警级事件附裁剪帧。全量事件随遥测导出（CSV/JSON/JSONL），构成 §12 评测与 §11 复训的数据底座。schema 契约有单测把守（必需键齐全）。

**告警出口（M5）**：可靠性主链是**确定性**的：`证据事件 → Effect Policy（模式包数据）→ Outbox（本地持久化，at-least-once）→ sinks`：`hud`（默认）/ `snapshot`（事件快照落盘）/ `webhook`（JSON POST，重试退避）/ `MQTT` / `email` / `本地声光` / **MCP 适配器（可选）**。MCP 只能作为出口适配器之一（服务 Agent 生态：查事件/调证据/请求复析/建工单），**不得作为告警主链**——模型工具调用无法提供 at-least-once、幂等与确定性重试；幂等与去重由 `event_id` 承担（§19）。出口不改变告警语义，只做路由。

## 16. 检测器可替换性与许可证退出路径

模式包把检测模型抽象为 `detector` 配置，**架构上检测器可插拔**。扩展不走 engine 枚举膨胀（onnx|mock|webgpu|remote|…），统一 **DetectorProvider 契约**：`load(config) / infer(frame, ctx) / health() / close()`——engine 名称只是 provider registry 的键；能力声明（输入/输出类型、是否产事件）与运行属性（并发/背压/超时/错误降级）随 provider 注册（契约借鉴 Vision Agents processor 设计，见 §19）。已注册：`yolo8head`（前身仓无人机模型）、`nanodethead`（NanoDet GFL 分布回归，person 模型）、`mock`（确定性时间线）。

现用 YOLOv8 权重 AGPL-3.0 传染、DINOv2 权重 CC-BY-NC 非商业——演示与科研无碍，**商业化前必须替换**：检测器换宽松许可架构（现代 opset 重导出，顺带解决量化失效问题；人员检测候选 RF-DETR 待许可证单独核实，§19），判别塔确认商用条款或换自训塔。该决策进 M5 前置清单，属用户商业裁决项。

## 19. 相关工作与借鉴：Vision Agents 调研（2026-09-09）

**调研对象**：GetStream/Vision-Agents（Apache-2.0，Python，8.1k star，v0.6.x）——实时语音/视频**会话** Agent 框架：可插拔帧处理器（ultralytics/Roboflow/自定义 ONNX）+ 实时多模态 LLM（Gemini Live / OpenAI Realtime）+ STT/TTS + 工具调用/MCP。**与本仓的关系判断：不同问题域（会话式互动 vs 事件式 24×7 场所监控），采纳结论"参考，不引入"**——量化口径：直接引入框架 0%、复制代码 0–5%、借鉴接口模式 20–30%、借鉴运维设计 30–40%、不需要改变现有技术路线。

**传输依赖的准确表述**：默认与最成熟的生产路径依赖 Stream 云 RTC；框架接口层有 `EdgeTransport` 抽象（存在 Tencent RTC transport 等第三方实现），**并非硬绑定 Stream**——但目前没有现成的纯局域网/自托管 RTSP-WHEP transport 能满足本仓"视频不出场"红线，自行实现 transport 的成本也不值得。隐私冲突成立，理由是"无现成合规路径且自建不划算"，而非"框架做不到"。

**有分量的第三方佐证（官方 Current Limitations，可直接引用）**：持续视频约 30s 后上下文退化；多数场景需要专用小模型 + 大模型组合；纯视频流不触发实时模型响应（需音频/文本驱动）；小字识别易幻觉。——独立印证本仓"触发式慎思 + 事件驱动 + 端侧专用模型 + VLM 仅接灰区"的路线。定位为**强工程佐证**（另一个成熟团队独立遇到相同约束并选择了相似分工），不是科学证明，更不证明其在安防生产环境的 24×7 稳定性。

**采纳的模式**（按价值排序）：

1. **Processor/Provider 生命周期契约**（最高价值）：`load / infer / health / close` + 能力声明（输入/输出类型、是否修改媒体、是否产事件）+ 运行属性（并发/背压/最大处理帧率/超时/错误降级）+ 可观测性（耗时/跳帧/错误/模型版本）→ 本仓落地为 DetectorProvider 契约（§16）；
2. **Transport 与处理/策略解耦**（M4 方向）：`MediaTransport`（RTSP/WHEP/HLS/WebRTC/USB/文件）不进模式包、不与检测器耦合——传输源是部署属性，不是场所语义；分层为 MediaTransport / FrameProcessor（门控/检测/跟踪/判别）/ ModePolicy（schedule/zone/阈值/效果）；
3. **多路网关运维设计**（M4/M6 参考）：指标维度=活跃会话数/输入输出帧率/丢帧背压/processor 延迟/模型调用延迟/队列深度/重连次数/错误率/CPU·内存；部署上**先单机做实**（watchdog + SQLite/JSONL 证据 + Prometheus endpoint），做实后再考虑横向扩展，不照搬其 K8s 架构；
4. **MCP 仅作为可选 Effect Adapter**：告警可靠性主链必须是确定性的 `证据事件 → Effect Policy → Outbox → sinks`（webhook/MQTT/短信/本地声光/MCP 适配器）；**绝不允许"模型决定是否调用工具"成为告警主链**（模型工具调用无法提供 at-least-once/幂等/确定性重试；幂等由 event_id 承担）。MCP 适合的频段是 Agent 生态协作：查事件、调取证据、请求复析、建工单。

**明确不采纳**：Stream-first RTC 传输；会话/turn 驱动运行时；持续视频→实时 LLM 路径；云端检测为默认路径；模型驱动告警投递；Python 框架依赖。

**P1 选型已闭环**：NanoDet-Plus-m-1.5x@416 胜出（Apache-2.0，官方 ONNX，真实街景实测通过）；RF-DETR 因参数规模架构性超 wasm 门槛出局；YOLOX 0.1.1rc0 资产因现代栈全零出局。完整选型矩阵与解码契约见 docs/model-selection.md。
