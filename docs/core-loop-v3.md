## 0. 三个领域前提（重定义的出发点）

1. **监控画面无声**：vus 的 ASR 管线在本域不可用，一切语义只能来自视觉——桥/仲裁器全部纯视觉 prompt，事件命名依据 = 帧 + 结构化摘要。
2. **成像模态切换是常态**：监控相机 IR-CUT 滤光片在黄昏/夜间机械切换，整帧彩色↔黑白（红外）——帧级速度、一夜可振荡多次，必须是一等状态机，而不是漂移异常；
3. **学习目标 = 慢脑摊销**：不是"判别更准"，而是让重复出现的事件（上下班画面等习惯性场景）最终**不需要 LLM**——系统自行命名（信任分层管控，见 §5）。

## 1. 循环总览

```
Phase A 环境详析（首启一次，admin 可修正；重大漂移可触发重析）
   └─ 产出 EnvironmentModel（环境模型，边缘持久化，admin 可编辑）
Phase B 快系统值守（≥99% 时间）
   └─ EventSegmenter 持续把流切成"事件时间段"（SegmentRecord）
Phase C 慢脑命名（近实时，SLA ≤30s）
   └─ 未命中的段经桥送 LLM → 语义命名（"员工上班刷卡进入""疑似翻墙"）
Phase D 习惯化（PatternLibrary，学习主轴）
   └─ 重复模式命中 → 直接自命名不调 LLM；审计抽检+admin 金标抑制漂移
（告警链不变：规则命中/慢脑判定 → 四态裁决 → 证据事件 → Outbox → 出口）
```

## 2. Phase A：环境详析（Environment Profiling）

**触发**：首次启动；管理员点"重新详析"；重大漂移（§6）。

**采样**：详析窗缺省 **24h**（覆盖完整昼夜），采样 = 不同时段宽帧 + 活动目标裁剪帧（复用场景自识别的采样器，扩大窗口与样本量）。**渐进精化日程**（避免首夜盲区）：

```
T+15min   draft-0   草稿（昼间基线；夜间字段标"待观测"）
T+首个夜末 night-1  夜间基线补全（照明阈值/夜间参数剖面标定）
T+24h     full-0    完整版定稿（提醒 admin 修正）
之后       渐进维护   重大漂移触发重析，admin 随时可改
```

每版携带 `env_hash`（与 mode_hash 同构的配置指纹），证据事件同时记录两者——"当时的环境定义"可追溯。首夜（draft-0 期间）夜间参数取保守缺省剖面（更高噪声门槛 + record-only 倾向），night-1 标定后替换。

**产出 EnvironmentModel**（JSON，边缘持久化，admin 可编辑；修改即人工定稿，优先级最高）：

| 字段组 | 内容 | 来源 |
|---|---|---|
| `venue` | 场所定位（自由文本："厂区北门，双车道，行人为主"） | VLM 起草 + admin 修正 |
| `inventory` | 常规要素清单（人/车/门/路面/绿化…） | VLM 起草 + admin 增删 |
| `illumination` | 照明状态基线（§6 各状态阈值与剖面） | 自动标定 + admin 可调 |
| `zones` | 敏感区域（多边形 + 类别 + 滞留/计数参数） | VLM 建议 + **admin 绘制定稿** |
| `behaviors` | **危险行为定义（开放集）** | **admin 主笔**（VLM 可辅助起草） |

**危险行为定义**是本循环的关键数据结构——每条：

```json
{ "id": "fence-climb", "name": "翻墙",
  "description": "人员攀爬围栏或围墙进入，而非经由大门通行",
  "observable": "人体出现在围栏上方且越过",
  "proposalTriggers": ["zone-hit", "trajectory-discontinuity"],
  "evaluation": "mid-segment", "cooldownMs": 15000,
  "zones": ["perimeter"], "severity": "high" }
```

它是**慢脑 VLM 的判定依据（prompt 素材），不是端侧分类器**——开放集行为（翻墙/偷拍/车祸/滞留…不限清单）由"行为=数据"保证：admin 写下什么，慢脑就按什么判。诚实分工：快系统产出结构化信号（谁/在哪/路径/越线/滞留），**行为的语义判定发生在慢脑**（逐段或规则触发时）。

模板包（airfield 等）降级为 venue 类型模板起点；环境模型才是真正的部署产物。

### 2.1 Venue/Camera 双层模型（v3.2，为 M4 预留结构）

环境模型拆成两层，归属不同、生命周期不同：

| | VenueModel（场所级，多相机共享） | CameraModel（相机级，独立标定） |
|---|---|---|
| 内容 | venue 定位文本、**behaviors 危险行为定义**、模式库（PatternLibrary）、命名预算 | 照明基线与剖面、zones（多边形属于视角）、inventory 的视角子集、详析采样器 |
| 为什么 | "翻墙"是场所语义——换一台相机看北墙南墙，行为定义不变 | 多边形/照明是视角事实——换相机必须重标定 |
| 存储 | 同步到场所内各相机（桥分发） | 相机本地 |

模式库挂在 VenueModel，但**信任不跨相机自动迁移**（v3.4）：

```
VenuePattern（场所级逻辑模式）
├─ 共享：name、结构原型（signature 结构分量）、行为定义引用、count/version/统计
└─ CameraAppearanceProfile（每相机 × 每模态）
   ├─ camera-A/day-emb · camera-A/night-emb
   └─ camera-B/day-emb · camera-B/night-emb
```

- 视角/焦距/安装高度/遮挡/运动方向投影都是**相机事实**——视觉嵌入永不跨相机比对，day/night 双档案只解决模态维；
- 跨相机命中（南门段匹配到北门模式的结构分量）→ 只生成 **transfer-candidate**：经慢脑或 admin 确认后，'
  '为南门建立自己的 CameraAppearanceProfile 并继承名称（版本+1）；**不继承源相机的 trusted 权限直接自命名**'
  '——一个门口的人流模式不得污染另一个不同透视关系的入口；
- 签名中的区域分量按 zone id 归一化（相同语义的 zone 跨相机共享 id，admin 绘制时声明对应关系）。

## 3. Phase B：快系统值守与事件分段

快系统（门控→检测→跟踪→规则）承担绝大部分时间，新增 **EventSegmenter**：

- **起段**：活动开始（运动 + 确认轨迹，或规则命中）；
- **止段**：静默窗口（缺省 20s 无确认活动）**或**达到段上限（缺省 120s）强制切分——忙碌场景（商场人流）永不静默，靠上限保证段有限、命名管线不被饿死；切分点取活动密度最低处；持续大流量场景退化为"周期汇总段"（每 120s 一段，LLM 批量命名，§4）；
- **并发语义**：段是全局时间窗（不按轨迹切分），段记录聚合窗内全部轨迹摘要；跨段的同一长驻轨迹在两侧段中各自出现（按在场时长归属），不强行拼接；
- **段记录 SegmentRecord**：时间段、轨迹摘要（类别/数量/路径/进出区域/越线）、成像模态、规则命中、关键帧（首/峰/末）、**行为签名 signature**。

**signature** = 廉价结构特征组合：`类别集合 + 数量档 + 路径形状（进出场/穿越/滞留）+ 区域集 + 越线集 + 成像模态 + 时段桶（晨/昼/暮/夜）+ 时长档` + CLIP 关键帧嵌入。

**signature 匹配用相似度而非精确相等**（习惯化成败的关键）：
1. 结构分量做**加权 Jaccard**（类别集 0.3 + 路径形状 0.25 + 区域集 0.2 + 越线集 0.15 + 光照 0.1，数量/时长归档后比差）；
2. **CLIP 关键帧嵌入余弦相似度**为常态分量（非可选，0.3 权重与结构分量凸组合）；
3. 匹配阈值 ≥0.82 归入同一模式（阈值随审计不一致率自适应微调）：相似度度量同时抑制"误分裂"（同类不同签名→永远无法 verified）与"误合并"（异类同签名→错误自命名）。

## 4. Phase C：慢脑命名（近实时）

段结束 → 查模式库（§5）未命中 → 经桥送 LLM：段摘要 + 关键帧 + `behaviors` 行为定义表 → 返回语义名称（"员工上班刷卡进入""车辆驶过""疑似翻墙（命中围栏行为定义）"）。

- **SLA：段结束后 ≤30s 完成命名**——非机器人级硬实时，但对监控事件流属于"极高实时"；
- **命名与告警解耦**：命名是理解层（事件流可读性）；危险行为的告警判定独立发生（见下"段中即时判定"），不等待命名。

**命名预算与重要性门控**（成本红线在循环层的落点）：

1. 每场所命名预算（缺省 **30 次/小时**，与仲裁预算同构），超预算的段先排队、窗口滚动恢复；
2. **重要性门控**决定排队序：规则命中/敏感区相关 > 新 signature（疑似新模式）> 普通未命中段；同 signature 的重复段**只送一次**，其余段直接挂"待命名"占位名，预算恢复或模式 verified 后统一回填；
3. **批量合并**：同场所积压的多个未命中段合成一次 LLM 调用（一次判多段），摊薄成本；
4. **降级命名**（桥不可达/预算耗尽时的诚实语义）：以签名模板生成立即可读的占位名（"人员×2 进入 restricted-zone，滞留 45s，越线 0"），桥恢复后由 LLM 覆写——事件流永远可读，只是可读性分层。

**行为定义的可判定性协议**（v3.2——admin 写的定义必须"视觉可判"）：

1. 行为定义模板增加 **`observable`（可观测特征）字段**：这个行为在画面上"长什么样"（翻墙="人体出现在围栏上方且越过"、偷拍="手持设备对准敏感区持续指向"——若视角看不到设备，admin 应写明依赖的间接特征或降级为"可疑滞留"）；
2. VLM 判定协议带 **"undecidable" 诚实选项**：画面证据不足时返回不可判定而非硬猜——不可判定不产生告警，但计入该行为定义的"可判定率"指标，持续过低的定义在 admin UI 提示重写；
3. **误报反馈闭环**：admin 在事件列表标记误报 → 该行为定义自动追加一条澄清记录（负例描述："X 月 X 日 22:14 的快递员经过非翻墙"，作为 few-shot 进 prompt）——行为定义是**活文档**，随误报迭代越来越准；
4. 定义数量上限 32 条/场所（prompt 尺寸边界），超出提示合并或分级（低严重度走段末判定不走段中）。

**命名链诚实化**：自由命名只有 ollama VLM 能做——降级链 = `ollama VLM → 签名模板占位名`（v3.1 已有）；**CLIP 不承担命名**（它只能对候选名做分类，场景识别与嵌入相似度才是它的岗位）。

**命名输出规范**（prompt 约定）：`{name: ≤16 字中文名, conf, matchedBehaviors: [id|null], rationale: ≤30 字}`——名称面向 admin 的中文短语，rationale 供审计。

**端到端延迟预算表**（全链路 SLA 堆叠，P95）：

| 环节 | 预算 | 说明 |
|---|---|---|
| T0 门控 → T1 检出 | ≤2.5s | 触发式（400ms/巡检 5s 语义不变） |
| 规则命中（zone/line）→ 本地裁决 | ≤1s | 纯端侧 |
| 段中 behavior-check → 告警 | ≤15s | 桥+VLM，独立预算 |
| 段结束 → 命名（在线） | ≤30s | 命名预算内 |
| 证据事件 → Outbox 投递 | ≤5s + 退避 | at-least-once |

**危险行为段中即时判定**（告警时效的关键，不等待段结束）——**触发策略是行为定义的一部分**（v3.4，堵触发盲区：车祸/偷拍等开放集行为不一定命中 zone/line/dwell）：

每条行为定义必须声明可执行的廉价触发器与判定时机（schema 见 §2 示例）：

- **proposalTriggers**（端侧廉价检测器，命中才发起 VLM 判定）：`zone-hit`（关联区确认轨迹）/ `line-cross` / `dwell`（现有规则）/ `trajectory-discontinuity`（轨迹速度或方向突变）/ `close-proximity`（双目标距离骤减）/ `pose-change`（人员倒地——需姿态模型，标注 M4+ 可选，无模型不承诺）；
- **evaluation**：`mid-segment`（触发即判）| `segment-end-only`（无廉价触发器的行为**诚实降级**——UI 不得显示为实时告警行为，仅段末判定后出结果）；
- **behavior-check 预算**（独立于命名预算不等于无上限）：每场所并发 ≤2、单行为冷却 `cooldownMs`（缺省 15s）、队列上限 8、单次超时 20s；超限/超时/桥不可达 → 降级为段末复核（与命名降级同语义）——繁忙区域不得慢脑洪泛；
- 动作：触发即取当前帧+轨迹摘要送 LLM（`behavior-check` 消息，最高优先级）；判定走四态裁决：高置信 → 立即告警，置信不足 → escalate 仲裁队列；段结束时再做一次**完整段判定**兜底（段中判定只看了切片）。

## 4.5 IncidentStory：跨段事件关联（v3.2 新增）

单个段是碎片，admin 关心的是故事。**关联规则（端侧，确定性）**：时间相邻（间隔 ≤ 止段静默窗 ×2）且共享任一轨迹/区域/越线的段 → 候选合并簇；簇经 LLM 在命名时顺带判定（同批 prompt 附簇内各段摘要："这些段是否同一事件？给出事件名"）→ **IncidentStory** `{storyId, 段列表, 事件名, 时间跨度}`。

- 故事作为整体进事件流（比段更高的消费单元），Outbox 同发；
- 疑似危险行为的故事升优先级全簇送 behavior-check 复核；
- admin 纠正故事名 = 金标（与段命名同一反馈通道）。

### 4.6 证据修订契约（v3.4 冻结——新事件实体不塞旧信封）

`sc.evidence/v1` 面向单次确认目标；v3 新增的段/命名/故事实体冻结为三个独立 schema：

```
sc.segment/v1        { segment_id PK, camera_id, venue_id, t_start, t_end,
                       summary{类别/数量/路径/区域集/越线集}, signature, modality,
                       mode_hash, env_hash, keyframes[] }
sc.segment-label/v1  { segment_id FK, revision 自增, source: llm|pattern|template|admin,
                       name, conf, matchedBehaviors[], pattern_id+version|null, time }
sc.incident-story/v1 { story_id PK, revision, segment_ids[], name, t_span, source }
```

- **实体不可变、修订递增**：迟到命名/模式回填/admin 改名/故事追加段 = 追加新 revision，永不原地覆写已投递内容；
- **Outbox 投不可变完整快照**（消息小，不做 patch——简单正确）；消费者按 (entity_id, revision) 归并、以最新 revision 展示；
- admin 改名 = `source:'admin'` 的新 revision，下游据此撤销旧语义展示；
- 确认目标级证据（sc.evidence/v1）经 segment_id 与段/命名/故事关联，各自独立演进。

## 5. Phase D：习惯化（PatternLibrary）——学习主轴

模式条目：`{signature 模板, name, count, llmAgree 次数, state, lastAudit, expectedWindow{时段桶,模态}, version}`——version 随每次 admin 纠正/降级自增，命名事件记录所用版本（§数据落点），事后可追溯"这条命名是哪个版本的模式库给的"。

**生命周期（信任分层，v3.4——模型自洽不等于正确性）**：

```
draft（LLM 命名 1 次）
  → model-verified（连续 ≥5 次 LLM 对同类段命名一致——仅模型自洽）
  → human-verified（admin 确认该模式 ≥3 个代表性样本：覆盖昼/夜/不同数量档）
  → deployment-approved（该场所冻结验证集评测通过——M5 评测体系产物）
```

**自命名资格与安全边界**：model-verified 只可自动命名**非安全输出**（事件流可读性、故事名）；**安全相关自动语义输出**（行为告警判定、出口 `notify`）只接受 human-verified / deployment-approved——模型自洽永远不能代替金标；跨相机 transfer-candidate 的确认同样计 human 金标。

**"降低未经发现的漂移风险"的有界机制**（措辞即立场：本节是**风险抑制**，不是"保证准确性"——名称真实正确只能由人金标或验证集背书；5% 抽检不一致率是模型自洽指标，不是事件真实错误率）：

1. **审计抽检**：model-verified 自命名命中仍按 **5%** 概率送 LLM 复核；不一致 → 模式降级回 draft（**保留 count**，re-verified 只补差额）、恢复逐段送审，并提示管理员；
2. **admin 纠正 = 金标**：事件列表中管理员改名 → 创建/修复模式，权重最高，并使受影响 signature 立即重训；
3. **上下文进签名**：成像模态/时段纳入 signature，防"白天模式错配到夜晚画面"；
4. **习惯化 ≠ 习惯性盲区**（v3.2——trusted 模式内部仍有监视）：
   - 模式带**预期窗口**（learned：该模式历史上出现的时段/光照分布，±1 桶）；命中落在窗口外 → 照常命名但**标记 anomalous-context** 并提高该段审计抽检概率；
   - **段内偏离检测**（纯端侧，不依赖 LLM）：trusted 命中段内若规则照常命中（越线/滞留）或数量档超模式历史 P95（上班人流 20 人，今天 2 人=模式命中但异常稀薄）→ 该段升级送 LLM；
   - 一句话：**模式只摊销"命名"，永不豁免"规则与偏离"**——规则在 trusted 段内照常触发告警。

效果：LLM 调用随时间摊销到只剩"新事件 + 抽检"——上下班画面自行命名，慢脑成本趋向常数。

**与旧学习叙事的关系**：探针自训练（DINOv2 头）保留但默认关、叙事降级；本循环的学习主轴是**事件模式习惯化**。

## 6. 成像模态状态机（ImagingModality，ICR 感知）——新的一等公民

**现象重述**（用户领域纠正）：监控相机在黄昏/夜间由 IR-CUT 滤光片机械切换日夜模式——**整帧从彩色变为黑白（红外辅助照明）**：切换在 1~3 帧内完成（机械动作 ~100ms 级）、色彩饱和度瞬间崩塌、噪声水平抬升、红外反射使植被/衣物亮度异常；且黄昏阈值边界、车灯反复触发会使**一夜切换多次（振荡）**。这不是亮度渐变，是成像模态跳变——先前"60 秒滞回"的亮度模型作废。

### 6.1 切换检测：多信号表决，硬件信号优先

- **信号优先级**：相机硬件日夜事件（ONVIF DayNight / 厂商 SDK 回调——存在即优先采用，图像推断只作兜底）> 图像推断表决（2of3）：**饱和度崩塌**（主信号）+ **噪声水平抬升**（IR 高增益）+ 亮度结构跳变——单靠饱和度在低饱和白天/雾天/编码色彩异常下会失效 > 时间先验（日出日落表仅 sanity 参考，不判定）；
- **原生黑白相机**：配置声明后常驻 `NIGHT-BW` 剖面，不参与切换检测；
- 与瞬态光区分：车灯/探照灯是同模态亮度尖峰（饱和度不变）；ICR 是跨模态跳变——两个检测器、两套处置；
- 状态全集：`DAY-COLOR` / `NIGHT-BW` / `NIGHT-LIT`（夜间彩色常亮：夜亮度且饱和度保持 ≥60s；独立剖面，接近昼剖面但噪声高）/ `TRANSITION` / `OSCILLATION`。

### 6.2 转移表（可判定协议，候选确认 N=3 帧）

| 当前态 | 观测 | 下一态 | 即时动作 | 学习动作 |
|---|---|---|---|---|
| DAY-COLOR | ICR 离开候选（饱和度崩塌等 2of3）持续 N 帧 | TRANSITION | 软重置门控背景、抑制假触发、立即切夜间剖面 | **冻结** |
| TRANSITION | 夜间特征稳定 N 帧 | NIGHT-BW / NIGHT-LIT | 恢复常规检测（夜间剖面） | 新 learning episode（几何 track ID 延续） |
| NIGHT-* | 90s 最小驻留内反向候选 | 记账 + **立即换回对应剖面**（参数跟物理事实走）+ OSC 计数 | 同 TRANSITION 处置 | 保持冻结至稳定 |
| NIGHT-* | 10 分钟滑动窗内 ≥3 次切换 | OSCILLATION | 双剖面保守并集（**实际值由详析分模态标定插值，未标定时退夜间剖面**——不拍脑袋取"conf 低+噪声高"）、新轨迹语义告警延后 | 冻结 |
| OSCILLATION | 单模态稳定 5 分钟 | 对应 DAY/NIGHT | 退出振荡，恢复单剖面 | 新 episode |
| 任意 | 进程重启 | 上一持久化态 + 重启观测 5s 再定 | — | episode 边界以持久化历史为准 |

- 滑动窗定义：10 分钟滑动窗（毫秒时间戳，含头不含尾）；切换历史持久化，重启不丢；
- 跨窗三边界：**几何 track ID 延续**（跟踪不中断）/ **学习 episode ID 重建**（学习永不跨窗）/ **IncidentStory 允许跨 ICR 窗关联**（故事是语义层，不受成像模态影响）。

### 6.3 切换窗处置（切换前后各 ~1.5s 标记 `icr-transition`）

1. **运动门控软重置**（吸取 vus 慢系统漂移修复的同族经验）：切换瞬间整帧变化必然引发帧差爆炸——**重置门控背景基准 + 抑制该次假触发**（不计入段活动、不启动检测），而非让流水线把切换当成"全画面剧烈运动"；
2. **已有确认轨迹**：继续跟踪（轨迹是几何的，不依赖色彩），规则告警照常；
3. **新轨迹**：转换窗内降级 record-only（黑白/红外下检出质量未验证的帧不产生告警）；模态稳定后按 v3.2 unstable 语义补复核追发；
4. **学习冻结**（"保证不出错"的第一道防线）：转换窗内**一切学习暂停**——自训练不更新、模式计数不累计、质心/嵌入不并入、审计不计入；模态稳定后恢复；几何 track ID 延续、学习 episode ID 重建（学习永不跨窗）。

### 6.4 跨模态持续性（"持续性好"的机制化）

- **模式库跨模态双嵌入档案**：一个逻辑模式带 `day-emb` / `night-emb` 两个嵌入质心——**同一习惯事件昼夜两个长相、一个名字**（上下班画面白天彩色/夜晚黑白是一个模式，不是两个互相打架的模式）；计数、命名、版本跨模态共享，**永不因切换重置**；
- **嵌入同模态比对**：CLIP 嵌入只在同模态内比相似度（跨模态嵌入距离远，直接比对必然误判）；跨模态匹配退化为结构分量（签名其余成分），夜段先按结构挂靠、次日同模态再回填嵌入——模式自然长出第二个档案；
- **统计分桶按模态**：运动占比等漂移监控按模态分桶——昼夜切换不算漂移，同模态内的缓慢劣化才算（漂移定义回归本义）；
- **剖面参数进环境模型**：两模态的检测/门控剖面由详析分模态标定（详析窗本来就覆盖昼夜），`env_hash` 溯源。

### 6.5 数据生命周期（v3.4 冻结——实现阻塞项，不是补充说明）

介质 = IndexedDB（web/），stores 与缺省策略：

| store | 内容 | 保留 | 逐出顺序 |
|---|---|---|---|
| `keyframes` | 段关键帧 JPEG | 普通段 7 天；告警关联段随证据 30 天（治理可配） | 未命名段关键帧 → 已命名段关键帧 |
| `segments` | 段结构摘要（无图） | 30 天 | 最旧优先 |
| `stories` | 故事记录 | 30 天 | 最旧优先 |
| `patterns` | 模式库（嵌入质心，无原始帧） | 永久 | 上限 500 条/场所，超出按 count×recency 逐出仅 draft |
| `audit` | 审计/纠正/降级记录 | 90 天 | 最旧优先 |
| 帧环 | 前因帧 | 内存，不持久化 | — |

- 告警证据与普通段**不同保留期**（遵循主设计 §10 治理配置）；
- admin 纠正引用的原始证据被逐出 → 纠正记录保留文本、标记 `evidence-expired`（溯源链诚实断链标注）；
- VenueModel 多相机同步：**单写者原则**（admin 是行为定义/场所文本唯一写者，相机只读消费），桥分发带 `venue_rev` 版本向量，冲突时 admin UI 提示——相机之间不互写；
- 删除/导出/脱敏/访问控制：遵循主设计 §10；admin 删除模式 = 物理删除 + 事件流保留历史命名记录（审计链不篡改）；admin UI（M4-a）须加本地口令（单用户 PIN）。
