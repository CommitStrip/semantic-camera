# 核心循环 v3 —— 环境详析 → 快系统值守 → 事件分段 → 慢脑命名 → 习惯化

*2026-09-10 · 本文档重定义产品核心循环，取代 v2 的"模式包选配 + 闭集场景识别"循环；
主设计文档（semantic-camera-design.md）的流水线/裁决/证据/出口/桥机制全部沿用，本文只写循环层。*

---

## 0. 三个领域前提（重定义的出发点）

1. **监控画面无声**：vus 的 ASR 管线在本域不可用，一切语义只能来自视觉——桥/仲裁器全部纯视觉 prompt，事件命名依据 = 帧 + 结构化摘要。
2. **光照突变是常态**：黄昏昼夜切换、夜间车灯/探照灯瞬态致画面骤变——光照必须是一等状态机，而不是漂移异常。
3. **学习目标 = 慢脑摊销**：不是"判别更准"，而是让重复出现的事件（上下班画面等习惯性场景）最终**不需要 LLM**——系统自行命名并保证准确性。

## 1. 循环总览

```
Phase A 环境详析（首启一次，admin 可修正；重大漂移可触发重析）
   └─ 产出 EnvironmentModel（环境模型，边缘持久化，admin 可编辑）
Phase B 快系统值守（≥99% 时间）
   └─ EventSegmenter 持续把流切成"事件时间段"（SegmentRecord）
Phase C 慢脑命名（近实时，SLA ≤30s）
   └─ 未命中的段经桥送 LLM → 语义命名（"员工上班刷卡进入""疑似翻墙"）
Phase D 习惯化（PatternLibrary，学习主轴）
   └─ 重复模式命中 → 直接自命名不调 LLM；审计抽检+admin 纠正保准确
（告警链不变：规则命中/慢脑判定 → 四态裁决 → 证据事件 → Outbox → 出口）
```

## 2. Phase A：环境详析（Environment Profiling）

**触发**：首次启动；管理员点"重新详析"；重大漂移（§6）。

**采样**：详析窗缺省 **24h**（覆盖完整昼夜），启动 **15 分钟**后先产出可用草稿版；采样 = 不同时段宽帧 + 活动目标裁剪帧（复用场景自识别的采样器，扩大窗口与样本量）。

**产出 EnvironmentModel**（JSON，边缘持久化，admin 可编辑；修改即人工定稿，优先级最高）：

| 字段组 | 内容 | 来源 |
|---|---|---|
| `venue` | 场所定位（自由文本："厂区北门，双车道，行人为主"） | VLM 起草 + admin 修正 |
| `inventory` | 常规要素清单（人/车/门/路面/绿化…） | VLM 起草 + admin 增删 |
| `illumination` | 照明状态基线（§6 各状态阈值与剖面） | 自动标定 + admin 可调 |
| `zones` | 敏感区域（多边形 + 类别 + 滞留/计数参数） | VLM 建议 + **admin 绘制定稿** |
| `behaviors` | **危险行为定义（开放集）** | **admin 主笔**（VLM 可辅助起草） |

**危险行为定义**是本循环的关键数据结构——每条：

```json
{ "id": "fence-climb", "name": "翻墙",
  "description": "人员攀爬围栏或围墙进入，而非经由大门通行",
  "zones": ["perimeter"], "severity": "high" }
```

它是**慢脑 VLM 的判定依据（prompt 素材），不是端侧分类器**——开放集行为（翻墙/偷拍/车祸/滞留…不限清单）由"行为=数据"保证：admin 写下什么，慢脑就按什么判。诚实分工：快系统产出结构化信号（谁/在哪/路径/越线/滞留），**行为的语义判定发生在慢脑**（逐段或规则触发时）。

模板包（airfield 等）降级为 venue 类型模板起点；环境模型才是真正的部署产物。

## 3. Phase B：快系统值守与事件分段

快系统（门控→检测→跟踪→规则）承担绝大部分时间，新增 **EventSegmenter**：

- **起段**：活动开始（运动 + 确认轨迹，或规则命中）；
- **止段**：静默窗口（缺省 20s 无确认活动）；
- **段记录 SegmentRecord**：时间段、轨迹摘要（类别/数量/路径/进出区域/越线）、光照状态、规则命中、关键帧（首/峰/末）、**行为签名 signature**。

**signature** = 廉价结构特征组合：`类别集合 + 数量档 + 路径形状（进出场/穿越/滞留）+ 区域集 + 越线集 + 光照状态 + 时长档`（可选叠加 CLIP 关键帧嵌入提高区分度）。它是 Phase D 匹配的键。

## 4. Phase C：慢脑命名（近实时）

段结束 → 查模式库（§5）未命中 → 经桥送 LLM：段摘要 + 关键帧 + `behaviors` 行为定义表 → 返回语义名称（"员工上班刷卡进入""车辆驶过""疑似翻墙（命中围栏行为定义）"）。

- **SLA：段结束后 ≤30s 完成命名**——非机器人级硬实时，但对监控事件流属于"极高实时"；
- **命名与告警解耦**：命名是理解层（事件流可读性）；危险行为的告警判定独立发生（规则命中即时 / 慢脑逐段判定），不等待命名。

## 5. Phase D：习惯化（PatternLibrary）——学习主轴

模式条目：`{signature 模板, name, count, llmAgree 次数, state, lastAudit}`。

**生命周期**：

```
draft（LLM 命名 1 次）
  → verified（连续 ≥5 次 LLM 对同类段命名一致）
  → trusted（admin 确认一次，或 count≥20 且审计零异议）
命中 trusted 模式 → 直接采用存名，不调 LLM
```

**"保证准确性"的诚实实现**（不盲信，错误率有上界）：

1. **审计抽检**：trusted 命中仍按 **5%** 概率送 LLM 复核；不一致 → 模式降级回 draft、恢复逐段送审，并提示管理员；
2. **admin 纠正 = 金标**：事件列表中管理员改名 → 创建/修复模式，权重最高，并使受影响 signature 立即重训；
3. **上下文进签名**：光照状态/时段纳入 signature，防"白天模式错配到夜晚画面"。

效果：LLM 调用随时间摊销到只剩"新事件 + 抽检"——上下班画面自行命名，慢脑成本趋向常数。

**与旧学习叙事的关系**：探针自训练（DINOv2 头）保留但默认关、叙事降级；本循环的学习主轴是**事件模式习惯化**。

## 6. 光照状态机（IlluminationMonitor）——新的一等公民

逐帧廉价统计（均值亮度/直方图/对比度，T0 级成本）→ 四状态：

```
DAY ──(持续 60s 暗于夜阈)──> NIGHT        NIGHT ──(持续 60s 亮于日阈)──> DAY
任一状态 ──(短暂尖峰, <60s)──> 保持原状态 + 帧标 unstable（TRANSIENT）
```

- **滞回**：状态切换需持续 60s 才生效——黄昏渐变与夜间瞬态光都不会引发模式抖动；
- **降级语义**：`unstable` 帧内的检出降级 **record-only**（不告警）——车灯扫过不产生误报，漏报由"状态恢复后继续跟踪"兜底；
- **参数剖面**：门控与检测参数按状态取剖面（夜间：更高 minArea 抗噪、更低 confThresh 补召回），剖面进环境模型；
- **与遮挡区分**：持续极端亮度 = 镜头遮挡（health 事件）；短暂尖峰 + 运动共存 = 瞬态光照；
- **漂移监控分桶**：运动占比等漂移统计按光照状态分桶，避免昼夜混统把正常切换误报成漂移。

## 7. 与现有实现的关系

| 现有资产 | 处置 |
|---|---|
| EdgeCore（门控/检测/跟踪/zone/line/四态裁决） | 原样保留 |
| 证据事件 / Outbox / webhook | 原样保留；SegmentRecord 命名后作为可读事件进事件流 |

| 场景自识别（§8.1 闭集选包） | **升级**为环境详析的起点采样器；闭集模板包 = venue 模板 |

**新增组件**：`EnvironmentModel`（含 admin 编辑）／`IlluminationMonitor`／`EventSegmenter`／`PatternLibrary`／命名管线／admin 编辑 UI（环境文本/zone 绘制/行为定义/事件纠正列表）。
