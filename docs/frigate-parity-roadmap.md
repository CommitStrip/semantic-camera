# 语义摄像头 v2 · 功能对齐路线图（标准：Frigate NVR）

> 状态：**待审阅**

## 0. Frigate 核心架构解读

Frigate 的成功密码（6000+ commits、20k+ stars 提炼）：

| 设计决策 | 为什么有效 | 我们怎么做 |
|---|---|---|
| **运动检测先行** | 先判断"有没有动"再跑昂贵的检测——资源省 97% | ✅ 已有（T0 帧差门控 1.6ms） |
| **可插拔检测器** | 检测后端是接口不是实现——Coral/GPU/CPU 随换 | ✅ 已有（NanoDet ONNX 可插拔） |
| **事件聚合审查** | 多目标合并为一个审查项（时间区间），用户逐个确认 | ❌ 缺——**最高优先级补** |
| **录像+回放** | 24/7 连续录 + 事件片段，用户回看有凭据 | ❌ 缺——**核心 UX 缺口** |
| **CLIP 语义搜索** | 缩略图嵌入→自然语言搜索历史事件 | 🔶 嵌入有（V-JEPA），**搜索 UI 缺** |
| **GenAI 描述** | 事件自动生成文本描述（OpenAI/Ollama） | ✅ 已有（VLM 命名+细节描述） |
| **通知系统** | MQTT/webhook/HA 推送，多通道 | ❌ 只有 webhook |
| **Live 多路网格** | 实时多相机画面 + 自动布局 | ❌ 缺 |
| **Birdseye** | 动态组合所有相机到一个视图 | 🔶 远期 |
| **配置热更新** | 改 YAML 不重启 | ❌ 缺 |
| **认证+TLS** | 内置认证、反向代理 TLS | ❌ 缺 |

## 2. 分冲刺路线图

### 冲刺 A：让用户看见告警（P1 核心）

**目标：管理员打开工作台就能看到"谁/何时/哪个区域/什么行为"+ 画面截图。**

| 任务 | 内容 | 验收 |
|---|---|---|
| A1 | 告警帧写入 SQLite（BLOB 列）+ GET /api/thumbnail/{event_id} | 浏览器看到告警缩略图 |
| A2 | 审查时间线卡片流（时间+缩略图+短名+严重度色标+区域徽章） | 悬停高亮+点击展开详情 |
| A3 | 事件详情弹窗（短名/细节描述/rationale/置信度/规则/误报按钮） | 标记误报 → DB 反馈 |
| A4 | 告警横幅（新告警时顶部红色横幅+点击跳转详情） | 新告警 3s 内出现在值守页 |

**工作量**：约 2 天（server.py 加缩略图端点 + web/index.html 重写为 SPA）

### 冲刺 B：录像系统（NVR 的本职）

| 任务 | 内容 | 验收 |
|---|---|---|
| B1 | ffmpeg 分段流拷贝（子码流 10 分钟段，-c copy 零 CPU） | 分段文件完整可播 |
| B2 | 保留策略（按天数+容量双闸） | 删旧正确、水位触发正确 |
| B3 | 事件片段导出（告警时从分段中截取 mp4） | 告警附带可下载的 mp4 片段 |
| B4 | 录像状态页（每相机今日/本周/磁盘占用/最近分段列表） | 工作台可见存储状态 |

**工作量**：约 2 天

### 冲刺 C：语义搜索 + 多相机（V-JEPA 嵌入的价值兑现）

| 任务 | 内容 | 验收 |
|---|---|---|
| C1 | 嵌入入库（SQLite embedding 列，每段关闭时自动存） | 嵌入可查 |
| C2 | 语义搜索（嵌入余弦→Top-K 相似事件） | 输入描述→返回相似事件列表 |
| C3 | 多相机值守网格（N×M 实时快照+告警徽章+点击切换） | 2+ 路同时显示 |
| C4 | Birdseye 简化版（所有相机快照拼图+告警高亮） | 多相机一览 |

**工作量**：约 2 天

### 冲刺 D：通知 + 集成

| 任务 | 内容 | 验收 |
|---|---|---|
| D1 | webhook 通知（POST 告警 JSON 到用户指定 URL） | 告警时外部 URL 收到 POST |
| D2 | MQTT 出口（paho-mqtt，topic: scam/{camera}/alarm） | MQTT 客户端收到告警 |
| D3 | 配置热更新（SIGHUP 或 API 端点→重读 venue.json） | 改配置后不重启生效 |
| D4 | API 认证（Bearer token 或 session） | 无 token 请求 401 |

**工作量**：约 2 天

### 冲刺 E：稳态验收（五线报告）

24h 浸泡 + 五线报告——**前置：真实 NVR 硬件 + 至少一路 RTSP 流**。

## 4. 不做的（边界即定位，与 Frigate 的差异是特色不是缺失）

| Frigate 有 | 我们不做 | 理由 |
|---|---|---|
| Coral TPU/EdgeTPU | onnxruntime 够用 | 降低硬件门槛 |
| TensorFlow 检测 | onnxruntime | 轻量 |
| 音频检测 | 监控无声 | 不适用 |
| PTZ 自动跟踪 | 需 PTZ 硬件 | 按需加 |
| 人脸识别 | 隐私争议 | 按需加 |
| LPR 车牌识别 | 超出定位 | 按需加 |
| 多用户 RBAC | 单管理员 | 简化 |
| Docker 容器化 | 纯 Python 直跑 | 降低门槛（后续可加） |
